# 苍龙升级成长 RNG

四档只影响 C++ 引擎的 `dragon_dos12` 升级规则。伤害、医疗、解毒、休息等战斗随机数，武功熟练度，以及吸内力带来的内力上限成长均沿用现有规则。`remake` 成长与 `MAX_ADD_PRO` 开关保持原有行为。

启用边界是 `[rules] progression=dragon_dos12`（或从 `profile=dragon_dos12` 继承）。其他模组默认的 `remake` 升级规则不读取这两项成长配置或浏览器偏好，不初始化种子、不解释角色余数字段，也不限制角色 0 的个人物品事件。仅选用苍龙战斗规则而保留 `remake` 升级规则时，同样不会启用这套功能。

## 玩家选择

在「系统设置 → 升级成长」选择；设置会写回当前模组的 `kysmod.ini`，下次启动继续使用。

成长选项从设置右侧展开为第四级菜单，前三列保持可见。四档同时展示说明，以 `[x]` 和「使用中」标明当前模式；选择后立即保存，左侧设置值同步更新。最大档的取舍单独分组，纵向列出「三维高、内力低」和「内力高、三维低」；其他档位下置灰并跳过键盘焦点。在「升级成长」按 →／回车／空格展开，↑↓ 选择、回车／空格确认，←／Esc／返回收起；也支持鼠标或触屏，点击左侧设置可直接返回并操作该项。网页版另外在当前浏览器保存成长偏好，刷新或重新打开后继续使用；游戏存档仍通过存档管理导出、导入。

也可直接配置：

```ini
[rules]
profile=dragon_dos12
growth_mode=original
growth_max_priority=stats
```

| `growth_mode` | 结算 |
| --- | --- |
| `original`（默认） | DOS 原版随机。连升时主属性共用一次抽签并乘升级数；医疗、用毒、解毒、拳掌、御剑、耍刀、暗器只各结算一次。可以通过 S/L 重抽。 |
| `fixed_random` | 每级随机，按本局种子、角色数组编号、目标等级、成长项目固定抽样。不消耗战斗随机数；读档、改变队员升级顺序或其他能力的成长资格不会重新抽这项成长。 |
| `average` | 每级取数学期望。生命取三个档位的中间值，符合门槛的能力每级 +1，三维共用半点余数；内力直接取自身平均值。 |
| `maximum` | 每级取可实现的极端结果。生命与各能力取最大值；三维与内力仍共用一次取舍，由 `growth_max_priority` 决定。 |

`growth_max_priority=stats` 表示三维优先，`mp` 表示内力优先。只有最大档使用这项设置。以资质 ≥90、默认成长系数为例：

| 档位 | 攻击、轻功、防御各增加 | 内力上限增加 |
| --- | --- | --- |
| 最大，三维优先 | 6 | 12 |
| 最大，内力优先 | 1 | 32 |
| 平均 | 3、4 交替（平均 3.5） | 22 |

平均档的兵器值不会因为半点处理而少加：原版 `0..2` 的平均值正好是 1，无需余数。医疗、用毒、解毒、拳掌、御剑、耍刀仍要求原值 >20；暗器从 0 开始成长。抗毒和特殊兵器不随升级成长。原有生命、内力和医疗等能力上限不变。

模式切换只影响未来升级，不补发历史成长、不更换种子、不清除已保存的半点。三维的同一个余数跨资质档位保留：已有半点时经过一个整数成长等级，半点仍在，下一个有半点的平均等级再补足。自定义成长系数先乘精确平均值再取整；奇数内力系数使用与三维相反的舍入相位，两次半点等级后达到精确总平均。

## R 数据布局

R 文件没有增加字节、记录、段或尾部数据。`TRole` 仍为 182 字节，六段索引和后续字段偏移不变；V4 检查点也仍直接包含原来的角色记录。

| 位置（角色记录内字节偏移） | 用途 |
| --- | --- |
| 每个角色的 `UnUse` / `Data[3]`，`+6..7` | `0x5000` 表示本格式且无半点，`0x5001` 表示有半点。其他旧值视作尚未初始化，首次平均升级时写入格式标记。 |
| 角色 0 的 `TakingItemAmount[0..3]`，`+174..181` | 四个非负 15 位数，共 60 位；低 32 位为种子，接着 12 位校验，最高 16 位 `0x4751` 为格式与版本标记。 |
| 角色 0 的 `TakingItem[0..3]`，`+166..173` | 必须全部保持 `-1`，让 DOS 和个人物品逻辑忽略对应数量。 |

外号 `Nick`、角色编号 `ListNum`、船字段、事件数据均未占用。种子只需保存一次，固定抽样无需可变计数器。版本 1 的抽样键与混合常量固定在 `rules/growth_state.cpp`，升级实现时不应任意改动，以免已有存档未来等级的结果变化。

新游戏创建独立种子；无界面前端按其可重复的新游戏种子流程生成，图形前端使用独立熵源。旧存档在读取角色段后，以载入角色字节的确定性哈希初始化，因此同一旧档重复导入不会得到不同种子。有效状态在原版、平均、最大三档中也保留，便于以后切回固定随机。识别到本格式但校验失败或版本不支持时会报错，不静默重新抽种子。

角色 0 有实际个人物品时不会覆盖；固定随机会报告冲突。指令 41 试图往已占用的角色 0 个人物品栏写入时会在修改前报错。主角平常使用的共享背包不受影响。随附苍龙数据及原 DOS 数据未发现把角色 0 作为敌人或给它个人物品的剧情调用；此保留约定不能直接推广到所有其他模组。

## 兼容性边界与验证

原 DOS 的角色段读写可以原样保留这些原有字段；它继续按自己的升级规则运行，也不会更新平均余数。往返 DOS 后的半点仅代表在本引擎平均档中积累的状态。

UPEdit Delphi 版本的字段定义和保存源码按普通 2 字节数字读写这些数量，没有发现保存时归零空物品数量的逻辑。其他工具若主动把空物品数量清零，会丢弃种子；完全清除格式标记后无法与老存档区分，将按确定性旧档导入。这是字段内容兼容的边界，不能保证任意编辑器保留自定义状态。

`bin-c/tests/dragon_rules_tests.cpp` 验证原版 DOS 抽签样例、四档与配置、固定随机的读档及升级顺序独立性、平均跨模式和资质的余数、最大取舍、元数据校验与冲突、原生 `LoadR/SaveR` 全字节往返，以及既有战斗回归。`tools/verify_growth_storage.py` 用指定原始 `Z.dat` 的机器码验证新字段内容通过 DOS 读取及角色段保存后仍原样保留。该验证采用隔离的 Unicorn 执行，不等同于完整 DOSBox 游戏会话；UPEdit 尚未进行真实 GUI 往返测试。

当前 R 有 589 条角色记录。隔离执行未经重定位的 DOS 静态地址时，角色 320 起的内存会与后续场景等数组重叠，未加元数据的基线也会发生同样覆盖。因此验证分为两项：角色段单独读取、保存时全字节一致；六段一起读取时，种子和前 320 个角色的半点保留，其他变化与基线一致。当前苍龙剧情的加入指令最高使用角色 92，位于验证范围内。不能把这项针对字段的验证当成扩展 R 数据在所有 DOS 启动器下完整兼容的证明。

```powershell
cmake --build bin-c/build --config Release --parallel 6
ctest --test-dir bin-c/build -C Release --output-on-failure
python tools/verify_growth_storage.py tmp/reverse/dragon-dos12/base/Z.dat game-data/kys-dragon/save/ranger.idx game-data/kys-dragon/save/ranger.grp
```
